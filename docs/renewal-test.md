# LG 하이케어솔루션 리뉴얼 테스트

기존 메인 화면과 분리된 리뉴얼 경로입니다. 사용자 배포 요청에 따라 2026-11-04에 최신 디자인·순위 강조·카테고리 및 테마 전체 보기의 상품목록 연결까지 배포했습니다. 콘텐츠 추가 제안은 제안 단계로 유지합니다.

## 배포 원칙

사용자가 해당 변경의 배포를 명시적으로 요청하기 전에는 로컬 수정·검증만 진행합니다. 이전 배포 승인은 후속 수정에 자동으로 적용하지 않습니다.

## 이번 수정

- [LG전자](https://www.lge.co.kr/)의 Pretendard 폰트, 16px 기본 본문, 큰 제목과 이미지 중심 배치를 참고했습니다. 폰트는 해당 사이트에서 사용 중인 공개 Pretendard 파일을 로컬로 저장했습니다.
- 본문 16~18px, 상품명 20~22px, 주요 버튼 16px, 보조 정보 13~14px을 기준으로 크기와 대비를 높였습니다. BEST 1은 데스크톱에서 두 행을 차지하는 큰 카드로, BEST 2·3은 우측에 배치합니다. 모바일에서는 BEST 1을 더 넓은 카드로 표시하고 가로 스크롤합니다.
- 배너와 상품 사진을 넓게 표시하고, 셀렉트는 54~56px 높이와 명확한 화살표를 사용합니다. 라디오는 원형 아이콘 없이 테두리와 배경으로 선택 상태를 나타냅니다. 네이티브 라디오와 키보드 조작, 포커스 표시는 유지합니다.
- 런타임 예시 상품·요금·임의 카드사·실적·24개월 조건을 모두 제거했습니다.
- 화면·제목·메타·접근성 라벨·인쇄물에서 테스트/프리뷰 안내 문구를 제거했습니다. 분리 경로와 `noindex`는 유지합니다.
- 견적 수량 입력을 제거했습니다. 한 항목은 한 제품이며, 과거 수량이 있는 저장 견적은 기존 금액과 혜택 합계를 보존해 독립 제품 항목으로 변환합니다.
- 견적 기본 화면에는 제품·모델·계약/관리·월 구독료와 수정/비교/상세 버튼을 짧은 행으로 표시합니다. 가입·프로모션 원문, 상세 계산, 선납, 카드·교원, 예상 총비용은 ‘요금 상세’ 창에서 확인합니다. 데스크톱 합계는 우측 고정, 모바일 합계·저장은 하단 고정 버튼으로 연결합니다.
- 인쇄/PDF 제품 부분을 표 머리글·번호·수량 칸이 없는 제품별 상세 리스트로 변경했습니다.

## 운영 데이터 연결

| 항목 | 사용 중인 원본 |
| --- | --- |
| 견적 모델·가격·옵션·이미지 | 기존 `/api/products?middle=...&groupBy=modelCode`, Drive의 `/api/image-proxy` |
| 메인 배너 | Firestore `mainBanners`의 활성 배너와 PC/모바일 이미지 |
| 테마상품 카드 요약 | `/api/renewal/theme-products`: 지정 모델 3개, 실제 최저가 옵션, 해당 모델 폴더의 대표 이미지 |
| 금주의 테마상품·BEST 3 | Firestore `mainThemeProducts/config`의 활성 카테고리·모델 순서 |
| 제휴카드 | 기존 `cardDiscounts`의 활성 카드, 금액, `allowTeacher` |
| 구독교원 | 기존 `teacherPlans`의 종류·구좌 제한·구좌당 할인 |
| 선납 가능 여부 | 기존 `/api/prepay/rate`, 실패 시 같은 Firestore `prepayRules`를 인증된 클라이언트로 조회 |
| 제품별 상품권 | 기존 `getVoucherMasterForModel` 및 `calcVoucher` |

메인의 **금주의 테마상품**은 관리자 `금주의 테마상품 관리`에 등록된 활성 카테고리만 탭으로 표시하고, 각 카테고리의 모델 목록 첫 3개를 BEST 1~3으로 표시합니다. 순위는 관리자 지정 순서이며 임의 판매 순위가 아닙니다. 미등록·조회 실패 모델을 다른 모델로 대신 채우지 않습니다. 운영 관리자 설정을 임의로 변경하지 않았습니다.

메인 BEST 카드에는 각 모델의 **실제 옵션 조합 중 최저 월 구독료**를 취소선으로 표시하고, 사용자가 요청한 **추가 10,000원 혜택 적용 시 금액**을 강조합니다. 0원 미만으로 내리지 않으며, 적용 조건이 있는 예상 혜택가임을 명시합니다. BEST 카드에는 옵션 정보가 나오지 않습니다. 이 표시용 혜택은 견적 계산에 자동 적용하지 않습니다. 가입·기간·관리·프로모션은 구독 조건 선택과 요금 상세에서 확인합니다. 또한 메인의 구독 조건 링크는 같은 최저가 옵션으로 견적 선택 화면을 엽니다. 매니저 견적은 가입 유형 → 계약 → 관리 → 프로모션 순으로 실제 variant를 선택합니다. 앞선 조건을 바꾸면 존재하는 조합 중에서 다음 옵션을 선택하며, 존재하지 않는 조합의 요금을 임의로 계산하지 않습니다.

요금 계산은 원본 `ProductCard.tsx`와 같은 기준입니다. 프로모션 선택 시 `할인후금액`, 미선택 시 `할인전금액`을 사용합니다. 72개월 선납은 할인 전 요금으로 선납금을 계산해 100원 단위 절삭하고, `(프로모션 반영 월 요금 × 72 - 선납금 × 1.135) / 72`를 100원 단위 절삭합니다. 카드 후 교원 할인을 적용하고 최종 금액은 0원 미만으로 내려가지 않습니다. 교원은 카드의 중복 허용 설정과 최대 4구좌 제한을 사용합니다.

카드의 실적·청구 할인 기간은 현 관리 데이터에 별도 필드가 없으므로 임의 값을 추가하지 않았습니다. 화면과 출력에 카드사 상품 조건 확인 문구를 표시합니다. 예상 총비용은 선택한 월 요금이 계약 기간 동안 유지되는 가정으로, 기간별 프로모션 일정 전체를 시뮬레이션한 확정 계약 총액이 아닙니다. 제품별 상품권은 표시하며 다품목 추가 상품권의 통합 계산은 아직 연결하지 않았습니다.

상품 조회 실패는 오류와 재시도를 표시합니다. 예시 데이터로 대신 표시하지 않습니다. 클라이언트 목록 캐시는 5분이며 서버는 기존 API 캐시 정책을 그대로 사용합니다.

## 로그인과 테스트 저장

- 기존 `UserProvider`와 Firebase Auth를 그대로 사용합니다. `users/{uid}`에서 읽은 role이 `manager` 또는 `admin`이어야 견적 작업 화면이 마운트됩니다.
- 기존 `ManagerLayout`과 동일하게 `isActive === false`인 매니저는 차단합니다. 관리자 처리도 원본과 같습니다. 로컬 `managerSession` 값만으로 접근을 허용하지 않습니다.
- 비로그인·일반 사용자·비활성 계정은 견적 데이터·저장 목록·제품 추가 모달을 볼 수 없습니다. 로그인 안내와 기존 `/manager/login` 연결을 제공합니다.
- 기존 로그인에 허용 목록 방식의 `next` 복귀를 추가했습니다. 리뉴얼 견적 경로만 허용하며, 일반 로그인은 기존대로 `/manager`에 도착합니다.
- 실제 운영 견적 DB와 통계에는 쓰지 않습니다. 테스트 견적은 `lgcare-renewal-test:draft:live-v2:{uid}` 및 `lgcare-renewal-test:saved:live-v2:{uid}`에 계정별로 저장합니다. 계정 전환 시 작업 상태를 다시 만듭니다.
- 이전 v1 예시 견적은 읽지 않습니다. 저장한 실제 데이터 스냅샷은 당시 가격과 조건을 보존합니다. 브라우저 데이터를 지우면 해당 테스트 견적도 삭제됩니다.
- 테스트 경로에서는 GA를 초기화하지 않으며 `noindex, nofollow, noarchive`를 유지합니다. 현재 권한 검증은 기존 사이트와 같은 클라이언트/Firebase 방식이며 새로 권한을 우회하는 API를 만들지 않았습니다.

테스트 항목은 실제 옵션 가격 사용, 허용 조합 제한, 원본 선납 절삭 계산, 수량·기간별 합산, 카드·교원 중복 규칙, 정상적인 0원 요금, 역할·비활성 매니저 차단, 계정별 저장 분리, 예시 견적 거부, 저장 당시 가격 보존, 기존 상품 API 호출·실패 처리, 한국 날짜, 로그인 복귀 경로 제한입니다.

자동 테스트 26개와 TypeScript 검사가 통과했습니다. 관리자 모델 순서·3개 제한, 실제 최저가 옵션 선택, 기존 수량을 개별 항목으로 변환하는 금액 보존 및 선납 API 실패 시 규칙 조회·실패 구분 검증을 추가했습니다. 운영 API에서 받은 정수기 50개 모델의 옵션 5,425개를 대조해 선택 월 요금이 원본 금액과 일치함을 확인했습니다. 프로덕션 빌드 및 메인·견적·기존 로그인·로컬 폰트의 HTTP 200 응답을 확인했습니다. 390px 모바일 화면에서 헤더, 활성 배너, 상품 배치를 확인했고, 별도 미로그인 창에서 견적 차단과 기존 로그인 화면 연결을 확인했습니다.

실제 API에서 상품 옵션·이미지 응답, 브라우저에서 활성 배너와 상품 카드 및 비로그인 견적 차단을 확인했습니다. 이후 제공받은 매니저 계정으로 별도 게스트 세션에서 로그인과 견적 복귀, 실제 최저가 옵션 선택, 제품 추가, 카드·교원 적용, 브라우저 저장을 확인했습니다. 비밀번호와 인증 토큰은 코드·문서·저장소에 기록하지 않았습니다.

현재 로컬 환경에는 Firebase Admin 환경변수가 없어 기존 선납 API가 500을 반환합니다. 리뉴얼은 이 경우 로그인된 클라이언트로 같은 `prepayRules`를 읽고 원본 API와 같은 모델 → 소분류 → 중분류 우선순위를 적용합니다. 읽기도 실패하면 선납 불가로 단정하지 않고 오류와 재시도를 표시합니다. 실제 모델에서 30%·50% 선택지와 선납금 재계산을 확인했습니다. 운영 API나 Firestore 권한 규칙은 변경하지 않았습니다.

실제 Chrome PDF 저장본을 렌더링해 단일 제품 A4 1쪽, 표 머리글·번호·수량 칸 및 테스트 문구 없음, 계약 월 요금·카드·교원·체감액 보존을 확인했습니다. 단일 제품은 상세 내역 자체가 합계이므로 중복 합계를 출력하지 않고, 여러 제품일 때 합계를 추가합니다.

최종 모바일 390px에서 금주의 테마상품 탭·BEST 카드와 견적 요금 상세를 확인했습니다. 별도 게스트 창에서만 제공 계정을 사용했고 검증 후 해당 창을 닫아 임시 인증·브라우저 저장 세션을 종료했습니다. 운영 관리자 설정 및 운영 견적 저장소에는 변경하지 않았습니다.

최종 변경 기준 전체 프로덕션 빌드도 성공했습니다. 기존 다른 화면의 lint 경고는 남아 있으며 리뉴얼 파일의 새 경고는 없습니다.

## PDF 시안에 맞춘 레이아웃과 테마 최적화

원본 디자인 제안의 2쪽 메인, 5쪽 통합 견적, 7쪽 옵션 설정 배치를 다시 확인했습니다. 메인은 넓은 배너 → 간결한 카테고리 → 제목 옆 테마 탭 → BEST 1을 강조한 상품 카드 → 짧은 혜택·상담 영역으로 정리했습니다. 견적은 행 단위 제품 목록과 우측 합계로 돌아갔습니다. 사용자가 이후 명시한 수량 입력·라디오 원형 아이콘·테스트 문구 제거 및 인쇄 리스트 형식은 유지합니다.

테마상품의 전체 옵션은 브라우저에 보내지 않습니다. 새 API가 실제 최소 요금과 해당 선택 조건만 전송하고, 같은 모델의 이미지 폴더만 조회합니다. 브라우저 요청과 서버 폴더 조회 모두 진행 중 요청을 공유합니다. 탭 hover/focus 시 미리 읽으며 유효 캐시가 있으면 빈 로딩 카드로 되돌아가지 않습니다. 상품 이미지는 Next.js에서 화면 크기에 맞는 WebP로 출력되는 것을 확인했습니다.
