# 제품 엑셀 통합 업로드 구현·검증

> 이 문서는 초기 로컬 구현 기록이다. 최종 운영에서는 현재 상품 값과 Drive 수동 업로드를 유지하며 이미지 자동 전환은 비활성화했다. 실제 배포·검증 결과는 [최종 운영 배포 기록](deploy-product-management-20261111.md)을 따른다.

2026-11-11. **로컬 구현과 검증만 진행했다. 운영 배포·상품 반영·시트 쓰기·이미지 업로드·Cloud Run 설정 변경은 실행하지 않았다.** 기존 인증·환경 파일과 사용자 개발 서버는 유지했다.

## 사용 흐름

관리자 `/admin/product-import`에서 받은 `.xlsx` 원본 하나를 업로드한다. 상품·디스클레이머·상품권을 각각 분석하며, 상품은 중분류를 자동으로 나눈다. JSON을 별도로 만들 필요가 없다.

1. 누락·중복·금액·날짜 오류와 원본 행 번호를 확인한다.
2. 반영 항목과 상품 분류를 선택한다. 기본값인 ‘추가·수정’은 파일에 없는 모델을 유지한다. ‘전체 교체’는 선택한 항목에서 빠지는 모델을 표시한다.
3. 준비된 변경 수와 모델별 변경 전·후 금액, 구독 조건, 상품권 지급 조건, 문구를 확인한다.
4. 검토 후 반영 버튼을 누르면 검증이 끝난 상품 버전으로 전환하고 선택한 항목을 사전 조회한다. 업로드만으로 현재 데이터가 바뀌지 않는다.
5. 필요할 때 이전 버전으로 되돌린다. 원본과 반영 이력은 보존한다.

상품 이미지는 별도 ‘이미지 동기화’로 기존 Drive 파일을 읽어 썸네일 WebP와 상세 JPEG를 만든다. 분류 전체의 변환이 성공해야 이미지 연결이 바뀌며, 중단한 작업은 이어서 처리할 수 있다. 기존 Drive 파일은 변경하지 않는다.

Google Sheets는 편집·보관용으로 유지할 수 있다. 선택적으로 반영된 상품 분류를 기존 시트에 복사하는 별도 동기화를 제공한다. 서비스 조회는 먼저 검증한 상품 버전을 사용하므로, 시트 복사가 중단돼도 공개 상품 데이터가 절반만 바뀌지 않는다. **버전이 적용된 항목의 운영 수정은 통합 업로드 또는 연결된 상품권 관리자에서 진행해야 한다. 시트만 직접 수정하면 해당 운영 버전에는 반영되지 않는다.**

## 운영 보호

- 개발 모드의 상품 버전·업로드는 `.product-catalog-local`에만 저장한다. 개발 모드에서 시트·이미지 동기화 쓰기는 거부한다.
- 2026-11-12부터 공개 상품 조회는 개발·운영 모두 운영에 반영된 업로드 버전을 읽는다. 개발 관리자 업로드·반영은 계속 로컬에 저장하며 공개 상품 조회에는 적용되지 않는다. 업로드된 버전이 없는 항목만 기존 시트 조회를 유지한다.
- 모든 신규 관리자 API와 캐시 변경 API가 서버에서 Firebase 로그인 토큰과 관리자 역할을 검증한다. 기존 비로그인 캐시 호출은 허용하지 않는다.
- SHA-256과 크기를 검증한 변경 불가 파일을 저장한 뒤, Firestore 트랜잭션으로 활성 버전 하나를 전환한다. 부분 준비 상태를 공개하지 않는다.
- 다른 관리자의 최신 버전 변경이나, 첫 전환 준비 중 기존 시트·상품권 설정 변경을 감지하면 다시 비교하도록 차단한다.
- 요청 중단·중복 실행·저장 오류에 대비해 작업 상태, 임시 파일과 처리 위치를 보존한다. 사전 조회 실패는 이미 완료된 정상 반영을 취소하지 않는다.
- 첫 전환 때 기존 데이터도 백업 버전으로 남긴다. 이후 시트 동기화를 하더라도 되돌릴 가격과 문구를 보존한다.
- 구독 조건과 상품권 조회에 데이터 버전을 연결한다. 요약 목록만으로 견적을 만들지 않고 선택한 모델의 전체 조건을 받은 뒤 계산한다. 기존 저장 견적의 금액은 새 마스터로 일괄 덮어쓰지 않는다.
- 활성 버전 확인은 최대 15초 간격, 변경 불가 데이터는 크기를 제한한 메모리 캐시를 사용한다. 동시에 들어온 동일 파일 조회는 다운로드 한 번을 공유한다. 일시적인 포인터 조회 실패 때 이미 확인한 버전은 유지한다.

## 최적화와 비용 범위

목록·검색은 전체 구독 조건 대신 모델별 요약을 읽고, 조건 선택 시 해당 모델 데이터만 불러온다. 반영된 분류는 서버 재시작 후에도 Google Sheets 전체를 다시 읽지 않는다. 이미지 동기화 후에는 Drive 프록시와 Next 이미지 변환을 거치지 않고 미리 만든 파일을 표시한다. 같은 원본 이미지의 해시가 같으면 변환 결과를 재사용한다.

Docker 실행 이미지는 빌드 도구 전체 대신 Next standalone 실행 파일만 포함한다. 실제 실행 검사에서 발견한 `async-function`의 Node 20 조건부 내보내기 파일은 명시적으로 포함했다. [Next 공식 문서의 파일 추적 설정](https://nextjs.org/docs/app/api-reference/config/next-config-js/output)을 기준으로 설정했다.

이 변경은 반복 API 호출·응답 크기·실시간 변환·실행 이미지 크기를 줄이기 위한 것이다. Storage 저장·전송 비용은 발생하며, **청구액 감소율은 실제 트래픽과 배포 후 지표 확인 전에는 확정할 수 없다.**

별도 읽기 전용 점검에서 현재 Cloud Run의 4 vCPU·8GiB, 최소 인스턴스와 이전 태그의 최소 인스턴스 설정을 확인했다. 고정 비용 축소는 코드 최적화와 별개로 크기·태그·최소 인스턴스 조정 검토가 필요하다. `scripts/cloud-run-cost-review.ps1`은 조회와 제안 출력만 수행한다. 운영 설정은 변경하지 않았다.

## 검증 및 남은 운영 확인

- 자동 테스트 109개 통과: 기존 견적·상품권·캐시 동작과 신규 변환·반영·되돌리기·실패 재시도·동시 변경·인증·동기화 보호.
- TypeScript 검사 통과. 신규 코드 ESLint 오류 없음. 전체 빌드는 기존 파일의 경고를 유지하며 통과.
- 기존 `.next`를 건드리지 않는 별도 폴더에서 운영 빌드와 standalone 실행 검사.
- 실행 파일로 관리자·견적 페이지 200, 비로그인 관리자 API 401, 기존 상품 목록·상세·상품권·디스클레이머 API 200 확인. `usp_wd522mh` 상세 조회도 200. 외부 서비스는 읽기만 사용.
- 실제 기존 정수기 데이터의 같은 51개 모델을 비교해 목록 응답 3,857,440 → 102,499바이트로 약 97.3% 축소 확인(이미지 제외, 전체 조건 5,520개 → 요약 101개). 선택 후 WD724RH 전체 조건 136개를 별도로 정상 조회. 비용 감소율을 뜻하는 수치는 아님.
- 새 화면 PC·모바일 렌더링 확인. 390px 화면의 문서 가로 넘침 없음. 화면 확인에는 검토용 고정 데이터만 사용.
- 실제 Google Sheets의 열 구성과 서비스 계정 편집 권한, 기존 Firebase Storage 버킷 존재를 읽기 전용으로 확인.
- 새 의존성의 실제 엑셀 파싱과 Sharp WebP 변환 확인. 변경 전·후 보안 감사에서 새 취약 패키지는 추가되지 않음. 기존 의존성의 감사 경고는 남아 있으며 이번 작업에서 일괄 업그레이드하지 않음.

이번 검증에는 실제 운영 저장소 쓰기·이미지 공개 URL 생성·시트 수정, Linux Docker 이미지 빌드를 포함하지 않는다. 로컬에 Docker 실행 도구가 없어 standalone 실행 파일을 직접 검증했다. 외부 쓰기 권한·실제 업로드와 배포 후 비용 효과는 별도로 확인해야 한다.

## 다음 배포 시 적용 순서

새 배포 요청이 있을 때 진행한다. 우선 원본 M18의 정확한 할인 전 금액을 수정한다. 새 리비전을 제한된 검증 주소에서 확인하고 기존 상품 상세·검색·견적·PDF·관리자 로그인을 점검한다. 전체 전환 전에 소규모 분류부터 통합 업로드의 비교·반영·되돌리기를 확인한다. 이미지와 시트 동기화는 개별 작업으로 확인하며, Cloud Run 자원 축소는 오류율·응답 시간·메모리 지표를 보고 별도 적용한다.
