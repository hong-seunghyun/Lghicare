# 제품등록 엑셀 통합 업로드 검토

점검일: 2026-11-11. 사용자가 지정한 `LG하이케어솔루션_제품등록_261105_수정.xlsx`를 읽어 현재 코드와 JSON 구조에 대조했다. 원본 엑셀·구글 시트·Drive·운영 데이터는 수정하지 않았다. 이전 대화 원문은 조회하지 않았으며, 별도 대화에서 정한 추가 변환 규칙은 이번 검토에 포함됐다고 가정하지 않았다.

## 확인한 데이터

| 원본 시트 | 유효 데이터 | 자동화할 작업 |
| --- | --- | --- |
| 제품등록리스트 | 21개 중분류, 757개 모델, 131,524개 조건 행 | 중분류별 분리, 헤더 정규화, 기존 시트에 맞춘 열 매핑 |
| 디스클라이머 | 34개 모델 | 모델코드와 문구를 기존 디스클레이머 형식으로 변환 |
| 상품권마스터 | 모델이 있는 행 783개, 고유 모델 782개 | 기본·서비스주기·프로모션·기간별·다품목 규칙으로 변환 |

`제품등록리스트`는 A:X 24열이고 헤더는 1행이다. `디스클라이머`는 A:F, 헤더는 1행이다. `상품권마스터`의 항목 헤더는 8~9행이고 모델은 10행부터다. 3~7행 X:Y에는 다품목 지급 구간이 있다. 핵심 세 시트에 수식과 캐시된 수식 오류는 없었다.

파일의 XML 범위나 서식이 적용된 행 수를 데이터 수로 사용하면 안 된다. 제품등록리스트 XML에는 131,777행이 있으나, 실제 모델코드가 있는 데이터는 131,524행이다. 상품권마스터도 서식 범위가 26,417행까지 확장돼 있으므로 모델코드를 기준으로 읽어야 한다.

원본의 `서비스\n주기/월` 헤더를 사이트의 `서비스주기/월`에 연결하고, `디스클라이머` 열을 기존 JSON 키 `디스클레이머`로 명시적으로 매핑해야 한다. 모델명과 프로모션명은 원문을 보존한다. 모델코드의 접미사를 일괄 제거하지 않는다.

## 검증 사례

- `제품등록리스트!M18`: WD724RK의 할인 전 금액이 공백이다. W18의 할인 후 금액 57,900원은 존재한다. 누락을 0원으로 변환하거나 다른 행 값으로 추정하지 않고 확인 대상으로 표시한다.
- `상품권마스터!A292:Y292`, `A296:Y296`: OLED65B6SS.AS20A가 중복되며, 두 행의 적용 내용은 같다. 동일한 중복은 한 건으로 정리하고, 금액·조건이 다르면 충돌로 표시한다.
- `상품권마스터`의 테마판촉 등록 모델 293개에는 2026-11-01~2026-11-09 기간이 있다. 점검일에는 종료된 상태다. 날짜를 현재 기간으로 임의 연장하지 않는다.
- 상품권마스터에는 제품등록리스트에 없는 모델 25개도 있다. 등록 예정·별도 운영 상품일 수 있으므로 즉시 삭제하거나 오류로 단정하지 않는다. 제품등록리스트의 757개 모델은 모두 상품권마스터에 존재한다.
- `상품권마스터!K11:N11`에는 WD724RH의 케어십전환 100,000원과 타사보상 160,000원이 직접 기록돼 있다. Y열의 ‘대수만 인정, 상품권 미적용’은 다품목 영역의 비고이며 개별 프로모션 상품권과 구분해 변환해야 한다.
- `상품권마스터!T8`에는 테마판촉의 ‘소상공인 타입 제외’ 조건이 있다. 일반 N 유형 전체와 같은 조건이라고 임의 해석하지 않고, 적용 대상을 명확하게 매핑해야 한다.
- 원본 디스클라이머 34건은 현재 `src/disclaimer/disclaimer.json`의 모델코드·문구와 정확히 일치한다.
- 저장소에 포함된 `promo_rules_final.json`은 이번 파일과 모델 구성·다품목 지급 구간·일부 기간이 다르다. 신규 반영 비교의 기준은 실제 운영 중인 상품권 설정이어야 한다.
- 엑셀에 내장 이미지 파일은 없다. 제품 사진은 기존 Drive 연결 또는 별도 이미지 업로드로 관리한다.

## 추천하는 첫 구현

현재 Google Sheets를 유지하면서 관리자에 ‘제품 엑셀 통합 업로드’를 추가한다.

1. 원본 파일 한 개를 업로드한다. 파일은 약 15.2MB이므로 업로드 후 서버 작업으로 읽고 진행률을 제공한다.
2. 핵심 세 시트를 각각 파싱한다. 행 번호와 원본 시트명을 보존해 오류 위치를 보여준다.
3. 운영 데이터와 비교해 신규·변경·유지·삭제 후보와 누락·중복·종료 기간을 표시한다. 파일이 월간 전체본인지 일부 추가본인지 선택하도록 한다.
4. 반영할 항목을 상품, 디스클레이머, 상품권별로 선택한다. 카드할인·LG구독교원·특장점·등록순서 시트는 기본 반영 대상에 포함하지 않는다.
5. 선택한 항목을 반영하고 결과를 기록한다. 변경한 분류만 캐시 갱신·웜업한다.

이렇게 하면 중분류별 필터·복사·붙여넣기와 외부 대화에서 JSON을 생성하는 작업을 없앨 수 있다. JSON 생성은 검증 가능한 고정 변환기로 처리하며, 관리자에게는 변환된 지급 조건과 금액을 보여준다.

## 현재 코드에서 필요한 연결 변경

- 상품 시트 쓰기: 현재 시트 조회 코드는 읽기 전용 OAuth scope다. 반영 API에는 별도 쓰기 권한과 서버 측 관리자 권한 검증이 필요하다. 업로드 직후 바로 운영 시트를 비우지 않고 준비·검증·반영 단계를 분리한다.
- 디스클레이머: 현재 제품 상세는 소스에 포함된 JSON을 정적으로 import한다. 관리자 반영만으로 표시가 바뀌려면 운영 저장소 조회로 변경해야 한다.
- 상품권: 기존 JSON 파서·정규화기를 재사용할 수 있다. 현재 importer는 파일에 없는 모델을 삭제하므로, 통합 업로드에서는 일부 추가/변경과 전체 교체 모드를 구분해야 한다.
- 반영 기록: 파일명·해시·반영 시각·처리자·항목별 변경 수·오류 위치를 보존하고, 실패한 작업만 다시 실행할 수 있게 한다.
- 여러 저장소 간 반영: Google Sheets와 Firestore를 함께 수정하는 작업은 단일 원자적 작업이 아니다. 전체 성공을 성급히 표시하지 않고 항목별 상태와 복구 수단을 제공한다. 이후 운영용 데이터 버전을 별도로 만들면 준비가 끝난 버전만 활성화하는 방식으로 개선할 수 있다.

구현 순서는 통합 업로드·검증 화면, 디스클레이머의 운영 저장소 연결, 상품권 변환기, 분류별 시트 반영·웜업 순서를 권한다. 상품 조회용 영구 데이터와 이미지 동기화는 이후 단계로 연결한다.
